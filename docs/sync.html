Sync

Synchronizacja

Getting the same notes onto a second machine you own. Between your machines and nowhere else — there is no hosted backend, no git remote, no S3.

Jak mieć te same notatki na drugiej swojej maszynie. Między Twoimi maszynami i nigdzie indziej — nie ma usługi w chmurze, nie ma zdalnego gita, nie ma S3.

Who pushes

Kto wypycha

The desktop app pushes; the server receives. A server never reaches out on its own — it waits. That is one fewer credential stored on a machine that sits exposed, and it matches the shape people actually have: distillation happens on the workstation with the GPU, and the results go to the box that stays on.

Aplikacja desktopowa wypycha, serwer przyjmuje. Serwer nigdy nie sięga sam — czeka. To o jedno poświadczenie mniej na maszynie, która stoi wystawiona, i odpowiada układowi, jaki ludzie realnie mają: destylacja dzieje się na stacji z GPU, a wyniki jadą na pudełko, które stoi włączone.

What travels

Co jedzie

Two separate things, with separate settings, because they behave nothing alike.

Dwie osobne rzeczy, z osobnymi ustawieniami, bo zachowują się zupełnie inaczej.

  • The knowledge surface — notes, skills, profile. Small, text, changes often. This is what agents read.
  • The blob archive — encrypted snapshots. Large, binary, changes rarely. Replicated by content hash, so a repeat run transfers nothing and an interrupted one resumes instead of starting over.
  • Powierzchnia wiedzy — notatki, skille, profil. Małe, tekstowe, zmienia się często. To czytają agenci.
  • Archiwum blobów — zaszyfrowane migawki. Duże, binarne, zmienia się rzadko. Replikowane po skrócie treści, więc powtórzony przebieg nie przesyła nic, a przerwany wznawia zamiast zaczynać od nowa.

Two things deliberately never travel: library.db, because it is a machine-local cache each side rebuilds for itself, and the vault ownership marker, because copying it would hand two machines the same claim.

Dwie rzeczy celowo nie jadą nigdy: library.db, bo to lokalna pamięć podręczna, którą każda strona odbudowuje sobie sama, oraz znacznik własności sejfu, bo skopiowanie go dałoby dwóm maszynom to samo prawo zapisu.

When both sides changed the same file

Gdy obie strony zmieniły ten sam plik

Nothing is overwritten. The local copy stays exactly as it is, the incoming one is written alongside it under a numeric suffix — note.md and note-2.md — and the conflict is counted, logged as a warning, and listed in the admin panel.

Nic nie jest nadpisywane. Lokalna kopia zostaje dokładnie taka, jaka była, przychodząca jest zapisywana obok pod numerycznym sufiksem — note.md i note-2.md — a konflikt jest liczony, zapisywany do logu jako ostrzeżenie i wypisany w panelu admina.

Why it is reported and not just resolved: keeping both copies and telling nobody is the same as a silent overwrite with better forensics. If you never learn a file diverged, you carry on editing one half of it.

Dlaczego jest zgłaszany, a nie tylko rozwiązywany: zachowanie obu kopii i niepowiedzenie o tym nikomu jest tym samym co ciche nadpisanie, tylko z lepszą kryminalistyką. Jeśli nigdy się nie dowiesz, że plik się rozjechał, dalej edytujesz jego połowę.

The distillation ledger is the exception, and it merges as a union of ids rather than conflicting. An entry that exists only on one side survives the sync, so neither machine re-distils a conversation the other already processed.

Wyjątkiem jest rejestr destylacji, który scala się jako suma identyfikatorów, zamiast wchodzić w konflikt. Wpis obecny tylko po jednej stronie przeżywa synchronizację, więc żadna z maszyn nie destyluje ponownie rozmowy, którą druga już przerobiła.

Asking a server what it has received

Jak zapytać serwer, co dostał

A headless server has no window to look at, so /healthz answers it: when the last transfer arrived, from which peer, how many files it carried, and how many conflicts have been reported since start-up.

Serwer bez okna nie ma gdzie tego pokazać, więc odpowiada /healthz: kiedy przyszedł ostatni transfer, od jakiego nadawcy, ile plików niósł i ile konfliktów zgłoszono od startu.

lastReceivedAt: null means nothing has ever arrived. That reads as an empty field but it is an answer, and it used to be indistinguishable from “something arrived and it was empty”. The file count belongs to the last transfer that actually delivered something, so a client merely polling cannot erase the record of the one before it. No token ever appears here.

lastReceivedAt: null znaczy, że nigdy nic nie przyszło. Wygląda jak puste pole, ale jest odpowiedzią — kiedyś nie dało się tego odróżnić od „coś przyszło i było puste”. Licznik plików należy do ostatniego transferu, który faktycznie coś dostarczył, więc klient tylko odpytujący nie skasuje śladu po poprzednim. Żaden token się tu nie pojawia.

After a sync, rebuild the index

Po synchronizacji przebuduj indeks

Files a replica received but never indexed are files no agent can find. The search would report success over an unchanged index while the notes sat on disk unreachable, so a receiving server exposes a reindex trigger and the transfer is not finished until it has run.

Pliki, które replika dostała, ale nigdy nie zaindeksowała, to pliki, których żaden agent nie znajdzie. Wyszukiwanie meldowałoby sukces nad niezmienionym indeksem, podczas gdy notatki leżą na dysku nieosiągalne — dlatego serwer przyjmujący wystawia wyzwalacz reindeksu, a transfer nie jest skończony, dopóki ten nie przebiegnie.

What this is not

Czym to nie jest

  • Not a backup. A conflict keeps both sides, but a deletion you push is still a deletion. Keep snapshots.
  • Not multi-user. One vault has one writer. A second instance over the same corpus serves read-only and names who holds the claim.
  • Not continuous. It runs when something asks it to, not on a timer watching the filesystem.
  • Not a cloud service. There is no hosted endpoint to sync through, by choice.
  • To nie kopia zapasowa. Konflikt zachowuje obie strony, ale skasowanie, które wypchniesz, dalej jest skasowaniem. Rób migawki.
  • To nie tryb wieloosobowy. Jeden sejf ma jednego piszącego. Druga instancja nad tym samym korpusem serwuje tylko do odczytu i podaje, kto trzyma prawo zapisu.
  • To nie działa ciągle. Uruchamia się, gdy coś o to poprosi, nie na zegarze pilnującym systemu plików.
  • To nie usługa w chmurze. Nie ma pośredniczącego punktu, przez który to idzie — z wyboru.
