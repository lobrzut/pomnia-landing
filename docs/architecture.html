Architecture in one screen

Architektura na jednym ekranie

Deeper map after the premiere story. First hold three boxes: your folder, the search card on this PC, the app. How distill/chunk/search work: How memory works. Below: vault vs AppData paths, unlock/lock.

Głębsza mapa po premiere’owym obrazku. Najpierw trzy pudełka: Gdzie są moje dane? — folder, karta katalogowa, aplikacja. Jak działa distill/chunk/search: Jak działa pamięć. Niżej: ścieżki vault vs AppData, unlock/lock.

Honesty boundary. Passphrase protects vault blobs (AES-256-GCM). Sidecars (skills/, USER.md, sessions/, distilled notes) and library.db are plaintext on disk. Disk access = readable memory without the password. Full trust text: Privacy · product SECURITY.md on GitHub.
Granica uczciwości. Hasło chroni bloby vaultu (AES-256-GCM). Sidecary (skills/, USER.md, sessions/, notatki distill) i library.db to plaintext na dysku. Dostęp do dysku = treść wiedzy bez hasła. Pełny tekst zaufania: Privacy · SECURITY.md w repo.

Unlock / lock

Unlock / lock

  • Unlock — passphrase derives the key (scrypt) into main-process RAM. Renderer never touches the vault filesystem; all ops go through IPC.
  • Lock — clears the key from RAM. Encrypted blobs stay sealed on disk.
  • Lock does not wipe AppData / library.db / vault sidecars. Searchable memory remains until you delete those folders.
  • Lost passphrase = vault blobs unrecoverable. There is no backdoor.
  • Unlock — hasło wyprowadza klucz (scrypt) do RAM procesu main. Renderer nie ma dostępu do FS vaultu; wszystko idzie przez IPC.
  • Lock — czyści klucz z RAM. Zaszyfrowane bloby zostają zamknięte na dysku.
  • Lock nie kasuje AppData / library.db / sidecarów vaultu. Pamięć do search zostaje, dopóki nie skasujesz folderów.
  • Utrata hasła = bloby vaultu nieodwracalne. Nie ma backdoora.

How MCP fits

Gdzie tu MCP

Assistants on disk → Backup/Import → Vault blobs (+ sidecars)
                              ↓ Distill / direct index
                         Brain library.db  →  MCP (:7862)
                              ↓
                    Cursor / any MCP client  →  search_library, get_user_profile, …
Asystenci na dysku → Backup/Import → Bloby vaultu (+ sidecary)
                              ↓ Distill / indeks bezpośredni
                         Brain library.db  →  MCP (:7862)
                              ↓
                    Cursor / klient MCP  →  search_library, get_user_profile, …
  • Embedded — Brain inside Pomnia on 127.0.0.1:7862; one MCP server pomnia; local Ollama for embed/search (and distill).
  • Remote brain-core — headless Linux; one key pomnia → /mcp + Bearer (often :7865). Local Ollama optional (distill only).
  • Step-by-step wiring: Connect MCP.
  • Embedded — Brain w Pomni na 127.0.0.1:7862; jeden serwer MCP pomnia; lokalna Ollama do embed/search (i distill).
  • Remote brain-core — headless Linux; jeden klucz pomnia → /mcp + Bearer (często :7865). Lokalna Ollama opcjonalna (tylko distill).
  • Krok po kroku: Podłącz MCP.

Footnote: a config that lists three SSE servers (pomnia + pomnia-vault + pomnia-library) is the retired Python hub. It is not a setup path. Connect → Remote does not emit it. There is one server, pomnia.

Przypis: konfiguracja z trzema serwerami SSE (pomnia + pomnia-vault + pomnia-library) to wycofany hub Python. To nie jest ścieżka setupu. Connect → Remote tego nie generuje. Jest jeden serwer, pomnia.

Two content pipelines

Dwa pipeline’y treści

InputPathNeeds LLM?
Chats (live backup, ZIP import) Vault → Distill → index Yes (default llama3.1:8b via Ollama)
Documents (PDF, DOCX, EPUB) Vault → Direct index (+ optional thin OCR) No (embed only; OCR = tesseract)
WejścieŚcieżkaLLM?
Czaty (live backup, import ZIP) Vault → Distill → indeks Tak (domyślnie llama3.1:8b przez Ollamę)
Dokumenty (PDF, DOCX, EPUB) Vault → Indeks bezpośredni (+ opcjonalny thin OCR) Nie (tylko embed; OCR = tesseract)

Do not distill PDFs — index them from Import. Skills live as plaintext under vault skills/ and are part of the knowledge surface.

Nie destyluj PDF-ów — indeksuj z Import. Skills leżą plaintext w skills/ vaultu i są częścią powierzchni wiedzy.

What is public vs yours

Co jest publiczne, a co Twoje

  • AGPL-3.0 product source (client, vault/crypto, embedded brain-core) — auditable; not a data leak.
  • This site (pomnia.ai) — marketing, outside the AGPL tree; no analytics cookies on privacy page claims.
  • Your vault + AppData — never published; protect the folders; unsigned Windows installer may trip SmartScreen (reputation, not a crypto claim).
  • No cloud sync in this early build; nothing leaves the machine without an explicit export/deploy you start.
  • AGPL-3.0 — kod produktu (klient, vault/crypto, embedded brain-core) audytowalny; to nie wyciek danych.
  • Ta strona (pomnia.ai) — marketing poza drzewem AGPL; privacy: bez cookies analitycznych.
  • Twój vault + AppData — nigdy nie publikowane; chroń foldery; unsigned Windows może złapać SmartScreen (reputacja, nie twierdzenie o kryptografii).
  • Bez syncu do chmury w tej wczesnej wersji; nic nie wychodzi bez jawnego eksportu/deployu, który uruchamiasz Ty.
