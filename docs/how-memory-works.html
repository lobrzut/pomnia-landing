Rule of thumb: distill dialogue, index finished prose. Do not run Distill on a PDF — that would ask a chat model to “summarize” a book you already have as text.

Reguła: destyluj dialog, indeksuj gotową prozę. Nie odpalaj Distill na PDF — to byłoby prośba do modelu czatowego o „streszczenie” książki, którą już masz jako tekst.

1. Distill (chats only)

1. Distill (tylko czaty)

Distill takes a raw conversation (from a live adapter or an imported archive) and asks a local Ollama chat model for durable knowledge only: summary, decisions, solutions, facts, open questions. Language is preserved (PL stays PL). Empty filler is rejected.

Distill bierze surową rozmowę (z adaptera live albo importu) i pyta lokalny model Ollama o tylko trwałą wiedzę: summary, decisions, solutions, facts, open questions. Język zostaje (PL zostaje PL). Pusty filler odpada.

  • Worth distilling? At least 3 messages and 200 characters of content — shorter chats are skipped before any LLM call.
  • Transcript budget: up to ~14 000 characters; longer chats send head + tail with a truncation marker.
  • Quality score (0–10): heuristic on specificity vs generic phrases. Below 5.0 → labeled garbage (or empty → stub).
  • Where the file lands: ok → vault/distilled/; stub/garbage → vault/distilled/_review/ (that folder is not walked into the search index).
  • After a good note: only the new .md paths are embedded into library.db (not a full vault re-walk).
  • Czy warto destylować? Minimum 3 wiadomości i 200 znaków treści — krótsze odpada przed LLM.
  • Budżet transkryptu: do ~14 000 znaków; dłuższe: head + tail ze znacznikiem ucięcia.
  • Quality score (0–10): heurystyka konkret vs ogólniki. Poniżej 5.0 → garbage (puste → stub).
  • Gdzie ląduje plik: ok → vault/distilled/; stub/garbage → vault/distilled/_review/ (ten folder nie wchodzi do indeksu wyszukiwania).
  • Po dobrej notatce: do library.db idą tylko nowe ścieżki .md (nie pełny spacer po vaultcie).

Distill vs “save to Pomnia” in chat

Distill vs „zapisz do Pomnia” w czacie

They are not the same file. Distill re-reads the raw adapter log later (batch, retroactive). save_conversation / checkpoint_session write what the agent structured now into sessions/ (or sessions/checkpoints/). Same topic can have both — two descriptions, not a 1:1 duplicate. Most sessions never get a manual save; Distill is how the backlog becomes memory. What runs without “zapisz”: Automation.

To nie te same pliki. Distill później czyta surowy log adaptera (batch, retroaktywnie). save_conversation / checkpoint_session zapisują to, co agent ustrukturyzował teraz, do sessions/ (lub sessions/checkpoints/). Ten sam temat może mieć oba — dwa opisy, nie duplikat 1:1. Większość sesji nie dostaje ręcznego zapisu; Distill ogarnia backlog. Co leci bez „zapisz”: Automatyzacja.

2. Chunking (how text is sliced)

2. Chunking (jak kroimy tekst)

Before embedding, text is split into overlapping windows. Same algorithm for distilled notes, session saves, and document pages.

Przed embeddingiem tekst idzie w nakładające się okna. Ten sam algorytm dla notatek distill, zapisów sesji i stron dokumentów.

  • Size: 1800 Unicode code points per chunk
  • Overlap: 200 code points
  • Prep: consecutive whitespace collapsed to single spaces
  • Breaks: prefers sentence boundaries (. , ; , newline, space) in the second half of the window
  • Documents: each PDF page is chunked separately; page_num is kept. Markdown/session notes use page_num = 1
  • Rozmiar: 1800 punktów kodowych Unicode na chunk
  • Overlap: 200 punktów kodowych
  • Prep: ciągi białych znaków → pojedyncze spacje
  • Cięcia: preferencja na granicę zdania (. , ; , newline, spacja) w drugiej połowie okna
  • Dokumenty: każda strona PDF chunkowana osobno; zachowywane page_num. Notatki MD/sesje: page_num = 1

packages/brain-core/src/rag/chunk.ts (CHUNK_CHAR = 1800, CHUNK_OVERLAP = 200)

Each row in the index stores roughly: path, display name, page number, chunk index, plaintext text, character count — plus a vector row keyed by the same id.

Każdy wiersz w indeksie trzyma mniej więcej: ścieżkę, nazwę, numer strony, indeks chunka, plaintext tekstu, liczbę znaków — plus wiersz wektora pod tym samym id.

3. Embeddings & library.db

3. Embeddingi i library.db

Embeddings come from local Ollama, model nomic-embed-text (768 dimensions). Text is asymmetric: documents are prefixed with search_document: , queries with search_query: (Ollama does not add these itself — Pomnia must).

Embeddingi z lokalnego Ollama, model nomic-embed-text (768 wymiarów). Wyszukiwanie jest asymetryczne: dokumenty z prefiksem search_document: , zapytania search_query: (Ollama sam ich nie dokłada — musi Pomnia).

  • Where: %AppData%/Pomnia/brain-core-data/library.db (or equivalent under ~/.pomnia on other OS) — plaintext chunk text + vectors. The vault password does not seal this file. See Where is my data?.
  • What gets walked on a full refresh: under the vault root, mainly distilled/, sessions/, library/ text — never skills/, _review/, blobs/, snapshots/.
  • Incremental: unchanged files are skipped via mtime+size, then content SHA-256 fingerprints in an indexed_files table. “Refresh index” should usually be fast after the first pass.
  • Documents: encrypted source stays in vault blobs; search uses a logical path like …/library/<docId> as the key in library.db.
  • Gdzie: %AppData%/Pomnia/brain-core-data/library.db (albo ~/.pomnia) — plaintext chunków + wektory. Hasło vaultu tego pliku nie zamyka. Zob. Gdzie są dane?.
  • Co wchodzi przy pełnym odświeżeniu: pod rootem vaultu głównie distilled/, sessions/, tekst z library/ — nigdy skills/, _review/, blobs/, snapshots/.
  • Przyrostowo: niezmienione pliki są pomijane (mtime+size, potem SHA-256 w tabeli indexed_files). „Odśwież indeks” zwykle jest szybkie po pierwszym przebiegu.
  • Dokumenty: zaszyfrowane źródło zostaje w blobach; wyszukiwanie używa logicznej ścieżki …/library/<docId> jako klucza w library.db.

4. Search / retrieval

4. Wyszukiwanie

MCP tool search_library (and the in-app search) run hybrid retrieval: embed the query → nearest vectors → boost by literal keywords in name/path/text → re-rank. Always PL+EN hybrid — there is no separate “knowledge language” switch (UI language is chrome-only).

Narzędzie MCP search_library (i wyszukiwanie w aplikacji) robi retrieval hybrydowy: embed zapytania → najbliższe wektory → boost słów kluczowych w nazwie/ścieżce/tekście → re-rank. Zawsze hybrydowo PL+EN — nie ma osobnego przełącznika „języka wiedzy” (język UI to tylko chrome).

What each hit returns:

Co zwraca każdy traf:

  • path — file (or logical library) path
  • chunkIdx, text — which slice, plaintext excerpt
  • score — combined score
  • meta — name, page, semantic score, keyword hit counts, optional penalties/boosts
  • path — ścieżka pliku (lub logiczna ścieżka library)
  • chunkIdx, text — który kawałek, excerpt plaintext
  • score — wynik łączony
  • meta — nazwa, strona, score semantyczny, trafienia keyword, opcjonalne kary/boosty

Ranking extras (on top of cosine similarity):

Dodatki do rankingu (obok podobieństwa cosinusowego):

  • Keyword in filename/path: +0.15 per term; in chunk text: +0.05
  • Path under _weak/: −0.15
  • Path under sessions/ (human / agent-written saves): +0.05
  • Recency for YYYY-MM-DD_… note names: up to +0.25 under ~30 days, fading to 0 by ~2 years (date from filename, not mtime)
  • Keyword w nazwie/ścieżce: +0.15 na token; w tekście chunka: +0.05
  • Ścieżka pod _weak/: −0.15
  • Ścieżka pod sessions/ (zapisy ludzkie / agentowe): +0.05
  • Recency dla nazw YYYY-MM-DD_…: do +0.25 poniżej ~30 dni, do zera ~2 lata (data z nazwy, nie z mtime)

What shifted recently (~last 1–2 weeks of product work)

Co się niedawno ruszyło (~ostatnie 1–2 tygodnie pracy produktowej)

If your mental model froze on an older build, this is the delta that mattered:

Jeśli Twój model myślowy zatrzymał się na starszym buildzie, to delta, która bolała:

  • Quality gate in the filesystem — low-quality distill notes go to _review/ (skipped by index); path-based ranking for _weak/ and sessions/.
  • Garbage threshold raised to 5.0 — more “generic OK” notes stay out of RAG.
  • Incremental indexing — refresh skips unchanged files; fingerprints in indexed_files.
  • No dual embed after distill — when embedded brain-core is running, only new note paths go into library.db; the old host-side JSON index is fallback only.
  • Nomic task prefixes fixed — documents and queries finally use the prefixes the model was trained for (previously assumed Ollama added them; it did not).
  • Chunking parity with the Python reference — Unicode code-point windows so Node and legacy indexes do not drift.
  • Recency by filename date — not by mtime (copying a vault no longer makes everything “brand new”).
  • Library consistency check — if the vault says a PDF is indexed but library.db has zero chunks, it is re-queued.
  • Quality gate w systemie plików — słabe notatki distill → _review/ (poza indeksem); ranking po ścieżce dla _weak/ i sessions/.
  • Próg garbage = 5.0 — więcej „ogólnie OK” nie wchodzi do RAG.
  • Indeks przyrostowy — odświeżenie pomija niezmienione; odciski w indexed_files.
  • Bez podwójnego embed po distill — gdy działa embedded brain-core, do library.db idą tylko nowe notatki; stary JSON index hosta to fallback.
  • Naprawione prefiksy nomic — dokumenty i query wreszcie z prefiksami, pod które model był trenowany (wcześniej zakładano, że Ollama je dokłada — nie dokłada).
  • Chunking zgodny z referencją Python — okna w punktach kodowych Unicode, żeby Node i stary indeks się nie rozjeżdżały.
  • Recency z daty w nazwie pliku — nie z mtime (kopiowanie vaultu nie robi wszystkiego „brand new”).
  • Spójność biblioteki dokumentów — jeśli vault mówi „zindeksowane”, a w library.db zero chunków — wraca do kolejki.
