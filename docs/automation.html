What actually runs by itself

Co naprawdę działa samo

Honest map of auto-save / auto-checkpoint / post-distill index & deploy. Pomnia is not a daemon that watches your IDE chats. Some steps are product pipelines; milestone “saves without zapisz” are agent + MCP discipline with a Settings gate.

Uczciwa mapa auto-zapisu / auto-checkpoint / indeksu i deployu po distill. Pomnia to nie demon, który podgląda czaty w IDE. Część kroków to pipeline produktu; „zapis milestone bez zapisz” to dyscyplina agenta + MCP z bramką w Settings.

One-line answer: Desktop never silently dumps a live chat. Distill runs when you start it. After distill, index (and optional remote deploy) can chain automatically. Mid-session milestones can land via checkpoint_session without saying “save to Pomnia” — but the agent must call MCP (rules + tool text tell it to). Full dump still needs the phrase.
W jednej linii: Desktop nigdy cicho nie zrzuca żywego czatu. Distill leci, gdy Ty go uruchomisz. Po distill indeks (i opcjonalny remote deploy) może się dołączyć sam. Milestone w trakcie sesji może wylądować przez checkpoint_session bez „zapisz do Pomnia” — ale agent musi wywołać MCP (reguły + opis narzędzia mu to każą). Pełny dump nadal wymaga frazy.

1. Auto-checkpoint (the “saves accomplishments” piece)

1. Auto-checkpoint (ten fragment „sam zapisuje osiągnięcia”)

Settings → Auto-checkpoint (autoCheckpointEnabled, default ON). When ON, MCP exposes checkpoint_session as a hard PRIORITY 2: after a real milestone (decision / fix+path / error+command / architecture) the agent should call it without waiting for “save to Pomnia”. Files go to vault/sessions/checkpoints/.

Settings → Auto-checkpoint (autoCheckpointEnabled, domyślnie ON). Gdy ON, MCP wystawia checkpoint_session jako twarde PRIORITY 2: po realnym milestone (decyzja / fix+ścieżka / błąd+komenda / architektura) agent ma to wywołać bez czekania na „zapisz do Pomnia”. Pliki → vault/sessions/checkpoints/.

  • Product does: gate (OFF refuses), quality gate (empty payload → no file), write markdown, then index that file into library.db.
  • Product does not: scrape the chat buffer on a timer. No MCP call → nothing stored.
  • Agent does: decide a milestone happened and call the tool. Connect / Brain Mode installs IDE rules (Cursor .mdc, CLAUDE.md, …) that spell this out; tool descriptions reinforce it.
  • Full conscious dump: still save_conversation only on the phrase → vault/sessions/.
  • Produkt robi: bramkę (OFF odmawia), quality gate (pusty payload → brak pliku), zapis markdown, potem indeks tego pliku do library.db.
  • Produkt nie robi: skanowania bufora czatu na timerze. Brak wywołania MCP → nic nie trafia do vaultu.
  • Agent robi: uznaje milestone i woła narzędzie. Connect / Brain Mode dokłada reguły IDE (Cursor .mdc, CLAUDE.md, …); opisy narzędzi to wzmacniają.
  • Świadomy pełny dump: nadal save_conversation tylko na frazę → vault/sessions/.

2. After you start Distill

2. Po uruchomieniu Distill

Distill itself is user-started (Brain tab or CLI). Once a run finishes successfully, the product chains:

Sam Distill jest uruchamiany przez Ciebie (zakładka Brain albo CLI). Po udanym runie produkt dokłada łańcuch:

  1. Write notes under vault distilled/ (quality gate: ok vs _review/).
  2. Auto-index new ok paths into embedded library.db when brain-core is running (not a full vault walk).
  3. Auto-deploy (optional): Remote master + “Auto-deploy after distill” ON → copy notes to KVM (SMB preferred) and trigger library/reindex.
  4. Ledger marks conversations processed so pending-only runs do not re-grind them.
  1. Zapis notatek w vault distilled/ (quality gate: ok vs _review/).
  2. Auto-indeks nowych ścieżek ok do embedded library.db, gdy brain-core działa (nie pełny spacer po vaultcie).
  3. Auto-deploy (opcja): Remote master + „Auto-deploy after distill” ON → kopia notatek na KVM (preferowany SMB) i library/reindex.
  4. Ledger oznacza rozmowy jako processed — pending-only nie mieli ich od nowa.

3. What people often overclaim

3. Czego nie należy przeceniać

  • No Desktop chat sniffer — tool text and product copy both say Desktop does not capture chats by itself.
  • No built-in scheduler — CLI docs mention you can cron the CLI with a passphrase; that is your OS job, not an in-app daemon.
  • Floating monitor — status PiP when minimized; opens “How it works”. Zero session capture.
  • Connect “wired” — MCP config file present ≠ agent already searched or checkpointed. Handshake + tool calls prove the loop.
  • Distill ≠ checkpoint — distill is retroactive LLM summary of adapter history; checkpoint is structured now from the agent. Same topic can have both.
  • Brak sniffera czatu w Desktop — opisy narzędzi i copy produktu mówią to samo: Desktop sam nie zrzuca czatów.
  • Brak wbudowanego schedulera — CLI wspomina, że możesz cronować CLI z passphrase; to zadanie OS, nie demon w aplikacji.
  • Pływający monitor — PiP statusu po minimalizacji; otwiera „Jak to działa”. Zero rejestracji sesji.
  • Connect „połączony” — plik MCP ≠ agent już szukał albo robił checkpoint. Handshake + wywołania narzędzi dowodzą pętli.
  • Distill ≠ checkpoint — distill to retrospektywne LLM z historii adaptera; checkpoint to struktura „teraz” od agenta. Ten sam temat może mieć oba.
